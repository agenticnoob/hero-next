# Hero Next 视觉与交互设计

本文件描述当前实现。验证范围与发布记录由 [STATUS.md](./STATUS.md) 管理。
移动端改造前的细节和历史截图证据保存在 [历史设计记录](./archive/2026-09-13-pre-mobile-visual-design.md)。

## 响应式边界

`src/shared/layoutTokens.ts` 的 `heroReadingQuery` 与 CSS 使用同一边界：
宽度不超过 900px、可用高度不超过 500px、无 hover 或粗指针，任一条件成立即进入阅读布局。
其余设备保留空间布局。共享 viewport store 订阅尺寸、根字号和输入能力变化，并清理监听器。
布局选择不依赖 UA。横屏触屏和接入鼠标前后的平板使用同一内容与章节顺序。

手机正文为 16–17px，文章正文 17px / 1.8 行高，安全边距至少 1.25rem。
正文最大行宽 42rem；标题最多 3.5rem，按容器换行。系统浏览器缩放未受限制，viewport-fit
为 cover。主题按钮、语言按钮与章节菜单保留至少 44px 触控目标和可见焦点，菜单可用 Escape 关闭。
菜单使用可访问名称标识的紧凑图标，放大文字时不会与双语控件重叠。

## 叙事与转场

顺序由 `src/chapters/definitions.ts` 唯一定义：自我、公理、构建、公共入口，最后是日志。
中英文内容源、公开链接与隐私边界保持一致。第一章不展示真实姓名、出生年份、城市、带日期的
教育/工作履历或服役经历；保留公开昵称与人物模型，四段内容分别介绍代表作品、全栈实践、工具判断和工程协作。

每章保持 Hub → 定向靠近 → 面投影 → 三角揭示 → 语义正文 → 三角收束 → 退回 Hub 的可逆路径。
空间布局沿用 600svh 进入、420svh 退出；阅读布局改为 110svh 进入、60svh 退出。
手机开场 Hub 至少占 100svh，介绍随文档自然滚动，中间 Hub 为 24svh。正文按实际内容展开，不再给段落添加多屏停留。
阅读布局的 Hub 文案使用清晰的上下编排，短横屏文案和模型分别占左右区域。
Hub 模型使用较小比例及下移位置，为介绍留出完整阅读区域。

章节菜单的链接交给既有 Lenis `anchors` 处理，立即跳转并同步同一滚动源。
文章目录使用真实锚点和 scroll-margin，保留顶部控件的空间。日志拥有真实 DOM 锚点，
不把 runtime timeline 的声明 ID 当作 HTML 锚点。原生滚动和 ScrollTrigger 的像素舍入会导致
完整进入时的进度略小于 1；仅在输入边界使用容差，内部旋转、投影和揭示仍连续。

布局变化通过合并的 animation-frame 刷新 ScrollTrigger 并更新进度；ResizeObserver 观察
实际章节和日志高度。字体、语言、分页和二维码展开后重新测量，避免保留过期的转场位置。

## 第一章：正文与个人模型

空间布局保留左右列、逐行避让模型与漫画气泡的排版，模型随正文完成一周确定性旋转。
阅读布局按原文顺序使用完整宽度：标题与简介、独立人物区域、四段叙述、结语。
模型区域拥有自然文档位置，应用 effect 将其实际屏幕位置映射到已有模型；人物随该区域滚出，
不会固定在正文中间遮挡文字。手机不运行逐行排斥测量或固定打字气泡。
模型仍使用同一个 GLB、managed scene 和 material，首面浮雕、入场与回贴关系保留。

仓库内 GLB 为 1,824,760 bytes，449,954 triangles，Draco 几何与 1024px WebP 纹理。
材质使用几何法线、0.12 emissive fill、0.72 roughness 和零 metalness；基色在两种主题下
固定使用 light token。源模型与派生几何在本次改造中未修改。当前未据浏览器模拟声称真机性能达标。

## 第二章：扇面目录与文章纸卡

空间布局保留同一 managed surface 的扇面标题与不同尺寸邮票纸卡，滚动驱动连续入栈，
正文溢出时分配对应的卡内阅读距离，减少动态效果时保留完整内容与选择语义。

阅读布局不挂载空间阅读 surface；顶部为可点击的文章目录，下方逐篇展示完整标题与正文。
点状纸边延续邮票视觉，目录可换行，每项至少 48px 高。文章没有内部滚动容器或正文裁切；
浏览器页面滚动就是阅读位置。最后一篇保留一屏减去锚点顶部间距的最小高度，确保短文的
目录跳转仍处于正文范围，不提前触发章节退出。所有文章保持稳定 ID，中英文使用同一注册表。

当前八篇命题由 AI 能力与个人评价、Agent-first 产品、语言与认知、自动化责任，以及
方案探索、工具判断、独立工作环境、文档与经验沉淀组成。中英文均以个人实践和开放问题
表达观点，保留原有四篇 ID；新增内容沿用同一目录、纸卡和滚动计算。

### 文字纹理清晰度

文字图集按每个标题、目录和正文块的实际尺寸排入行列，按高度排序并比较不同排列宽度，
优先保留采样密度，密度相同时减少分配面积。Canvas 绘制和 shader 共用明确的块坐标，
逻辑尺寸与实际像素尺寸分别记录；块间保留透明间距，避免相邻文字互相采样。
图集目标仍为 2 倍采样、单边最多 4096 像素，不增加纹理数量或可见画布。
当前八篇的实测密度与浏览器验收范围见 `STATUS.md`；文章增长后仍可能触发分辨率上限。

### 扩展文章

- 在 `src/axioms/content.ts` 的 `heroAxiomsArticles` 中增删或排序；每条记录需要稳定唯一的
  `id` 与 `translations.zh / translations.en`，字段为 `label / title / body`。
- 可选 `paper: { width: 0.92, height: 0.8 }` 控制大屏纸卡比例，取值 `(0, 1]`；省略时使用
  `config.ts` 的轮换尺寸。手机正文始终全宽，不受这些纸卡比例限制。
- `config.ts` 管理大屏每篇 0.9 屏滚动距离、圆弧、邮票边和纹理预算。当前八篇对应 820svh
  正文；阅读布局随内容自然展开，末篇保留上述锚点阅读高度。
- `reader.ts` 是注册表与大屏 artwork 的适配层；`frame.ts` 分配运动与溢出阅读进度。
  大屏并非无限文章库，规模明显增长时应另行设计分页或纹理窗口。

## 第三章：四面项目空间

大屏 fine-pointer 模式保留四个墙面、边缘转向、中央阅读、键盘选择和稳定源码链接。
退出与入场 atlas 均使用第一面构图，交互选择保存在项目 room store。

阅读布局保留四个普通项目与对应链接，改为自然高度的单列内容。标题和卡片间距收紧，
卡片正文至少 16px，外链保留 44px 触控区域。触屏不需要边缘鼠标手势，也不创建项目空间纹理。

### 四个项目详情与展台

AXMORF Studio、Viselora、SyringeMeter 和 Vibe Journal Pipeline 均提供中英文完整详情。
每个项目包含七节正文、六步流程、目录及项目链接，内容覆盖问题、设计取舍、个人角色和
当前边界。三个新增案例以长文阅读为主；只有 SyringeMeter 使用现有演示和真实截图。
四面墙均有对应入口，普通案例采用紧凑的文字入口区域；SyringeMeter 保持原有图文比例。

SyringeMeter 墙面保留精简介绍与源码链接，增加真实截图和“进入项目 · 观看演示”链接。
图片使用 room material 的 image-texture，入口文字进入同一墙面文字图集；两者都固定在
SyringeMeter 墙面坐标，不按 selected/settled 隐藏，转向两侧时随墙面连续透视和裁剪。
鼠标视差、转向和靠近由既有 shader 统一处理。语义链接以同一 view/approach 的逆投影
同步点击区域，保留可见侧面部分的命中；宽屏跨过近裁面的情况也裁剪判定。链接在屏外
或章节不可操作时不接收点击；hover 只锁边缘转向，不取消鼠标视差。
墙面图文与命中区域共享 `src/projects/exhibit.ts` 的布局，纯投影位于 `projection.ts`。
手机在普通项目条目中显示同一入口。点击后以既有 room
shader 的 approach uniform 沿当前墙面推进，原生 dialog 接管可滚动的语义正文。未新增
canvas、场景或运行时；高频推进量仍在 room effect 中插值。减少动态效果时直接打开。

展示地址为 `/projects/axmorf-studio`、`/projects/viselora`、`/projects/syringe-meter`
和 `/projects/vibe-journal-pipeline`。Next 拦截路由保留主页和 room store，直接访问或
刷新则呈现独立案例页。关闭按钮、Escape 和浏览器后退返回原墙面与滚动位置；浏览器前进
可再次打开。dialog 使用原生模态焦点约束，暂停既有 Lenis，并在卸载时清理视频、计时器、
滚动锁与焦点。详情与主页从根部 `HeroSiteStateProvider` 订阅同一主题和语言。
独立详情的返回链接指向真实 `#project-room`：桌面位于正文可交互中段，阅读布局位于正文
起点，避免落在 room 权重为零的入场边界。
首次从独立详情返回时，先等待实际 viewport 和既有滚动布局完成，再定位对应项目；
展台打开期间改变窗口尺寸，关闭时按新布局恢复到同一项目，并恢复可见入口的焦点。
阅读布局的返回位置限制在本章正文范围内，避免最后一张短卡片顶对齐时触发离场动画。
Next 16.2.10 存在直接访问静态目标后错误复用拦截缓存的问题（vercel/next.js#94533），
因此仅独立案例页使用 `force-dynamic`；主页和拦截展台仍静态生成，未升级框架或改写路由。

SyringeMeter 首屏是项目标题、简述和 16:10 视频。点击播放前只请求 poster；预览为 17 秒，完整版为
3:13，均保留原生 controls、playsinline，默认静音。片段入口为 00:18 实时测量、01:06
开始记录和 02:46 查看 CSV。选择新片段时清理旧播放请求，播放失败提供重试与视频直链。
七节中英文长文覆盖问题、测量、可靠性、记录、交付、个人角色和证据边界，配六步流程与
真实测量/CSV 截图。桌面目录随阅读停留，手机目录与正文单列排列，无独立的文章内滚动。
无 JavaScript 时独立页仍提供正文、目录和视频文件链接。

媒体位于 `public/projects/syringe-meter/`。网页完整版由用户提供的 showcase kit 转为
1440×900、24fps H.264/AAC、faststart，15,610,065 bytes；17 秒预览保留原有
1280×800 文件，7,263,801 bytes。原始 149 MB 完整录屏保留在站点仓库之外。poster 为
1280×800；两张正文截图分别来自完整版 02:00 和 03:00；OG 为 1200×630。

## 日志

数据继续由公开字段白名单静态导出，每天的日期、工具列表和 Timeline 事件保持配对。
浏览器进入第四章后按 manifest 请求内容哈希快照；错误、空状态和重试有中英文提示。
原事件保持作者提供的中文，不自动重写或展开私人日记。

阅读布局按源数据的日期倒序展示最近 12 天，每次加载 12 天更早记录，直到全部可读。
新增条目追加到已有 DOM 之后，保留已读节点和滚动位置，并通过状态文案提示显示数量。
手机日志使用普通单栏文档；不挂载透视文字组、不要求读者在运动中追踪文字。

空间布局继续使用最多十六天的原生 DOM-text/subtree 窗口：日期与工具在左、同日事件在右，
由同一进度沿透视路径经过。四面体保留阻尼推进、自旋和 Fresnel 提亮。
减少动态效果时移除推进、额外旋转与视差；大屏每次呈现完整的静止日期，手机仍为自然列表。

## 图集、颜色与 ownership

语义色仍只有两种：light `#C8C8C8`、dark `#424242`，正文对比度高于 4.5:1。
Hub 与正文以 committed theme 交换前景和背景。灯光颜色仍是独立照明输入，
不作为额外语义色。桌面空间布局在完整 Hub 上以真实 mesh hold 触发主题切换。
阅读布局在右上角语言控件旁显示半圆配色图标按钮，Hub 和各章正文均可点击，支持键盘操作，
双语可访问名称为“反转配色 / Invert colors”，`aria-pressed` 表示是否使用反转方案。
阅读布局禁用四面体长按；切入该布局时取消尚未完成的桌面长按，不拦截浏览器的原生上下文菜单。
按钮与桌面交互提交同一个 theme store，effect 将外部提交同步到材质和转场信号；不增加主题状态源。
按钮直接提交配色，无长按扩散动画；刷新保留已提交方案。开场提示随布局使用对应操作说明。

四面体的八个首尾端点保持 2 列 × 4 行图集，目标为 2 倍逻辑像素，整张纹理单边
最多 4096px。每块宽度上限从 1024px 提高到 2048px，高度上限仍为 1024px，
充分使用原排布的横向空间，减少靠近时低分辨率文字被放大的模糊。1440×900 时
每块为 1638×1024，1920×1080 时为 1820×1024；逻辑排版、UV、端点选择和
运行时纹理生命周期不变。实际分配面积增加，较大视口和倾斜侧面仍有采样限制；
不通过关掉 mipmap 或强行锐化文字来换取静态清晰度。

大屏 atlas 继续由共享 Canvas 排版模型绘制。阅读布局使用 `src/chapters/readingArtwork.ts`
读取实际正文首尾视口的 DOM Range 行位置、字体、边缘与已展开图片，不维护第二套窄屏文字宽度。
`readingLayout.ts` 的 revision 只标记低频布局失效，不是滚动状态；`atlas.ts` 预打包两个端点，
滚动时直接选用，不逐帧读取全部文字或上传纹理。Canvas 与 DOM 的抗锯齿仍可能略有差异。

- 一个 WebGLScrollRuntime、一个 canvas、一个 scroll truth、一个 committed theme。
- CSS 负责语义排版、颜色、可访问性、层叠和触控区域；WebGL 负责四面体、人物、投影与三角转场。
- 不增加第二 renderer、scene/pass、CSS mask/clip 转场、重复模型或页面级假 mesh press。
- 运行时 effect 和声明保持稳定；逐帧模型、shader 与过渡进度不进入 React state。
- 仅使用公开 Viselora entrypoints；不修改 npm 包，不引入邻接 checkout 或 runtime internals。
- 浏览器模拟与真机、多浏览器、主观视觉验收分别记录，不以无溢出替代可用性结论。
